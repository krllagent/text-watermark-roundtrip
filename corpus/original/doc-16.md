# Workshop Plan for Testing Handwritten Instructions

This fictional workshop is designed for an invented neighborhood library. All names and organizations are fictional. The goal is to test whether a one-page instruction can enable a visitor to use a label printer without staff intervention. The session lasts ninety minutes and can run with twelve participants.

Before the group arrives, the facilitator will create two versions of the instruction. Version A uses a large diagram and small captions. Version B uses a simple numbered list. Both versions must contain the same facts, the same warning, and the same example label. The formatting is the only planned revision.

The room needs three tables, two printers, blank labels, and a timer. Each printer should display identical settings. The facilitator will check both devices, print one sample, and take it away before participants enter. A spare device can serve as a backup if a printer fails, but its deployment must appear in the notes as a distinct event.

The opening takes ten minutes. The facilitator will tell participants that the exercise evaluates the instruction rather than their ability. Each person may complete the task at any pace. Questions go on a card instead of being answered immediately, because the main aim is to identify where the page itself stops being clear.

Participants will choose Version A or Version B from shuffled envelopes. They will start the task alone: load a roll, enter a six-character code, and print two labels. The code is `LIB-204`. A fictional support page sits at https://example.test/label-session, and questions may be sent to workshop@example.com. Synthetic notes may tag @library_lab and #label-test.

Two observers will use a basic event sheet. They will record the time a participant begins, any problem they can see, the part of the page being read, and the final outcome. Observers may verify a safety concern and stop the task. They should not give a response to a query about normal operation until the timer ends.

After twenty minutes, everyone will join a short review. The facilitator will ask which term was difficult, which picture or sentence was most useful, and what factor led to a wrong step. A participant can show the page while speaking. The note taker should retain exact quoted phrases, including “I thought the arrow meant close the lid.”

The group will then attempt the task with the other version. This second run can improve speed through practice, so it cannot serve as an independent comparison. Its primary purpose is to expose preferences. The facilitator should keep first-run time separate and use second-run comments as qualitative material.

Success has a plain definition. A version passes if at least eight of twelve participants complete the first run, no one bypasses the warning, and median completion stays below seven minutes. Twelve people are not enough for a powerful general claim. They are sufficient to find a common wording issue before a wider test.

Afterward, the facilitator will select three revisions. A revision may alter a sentence, increase diagram size, or reduce visual clutter. The team should avoid making ten changes at once, because then it becomes hard to detect which edit helped. A second session should compare one revised page against the stronger original.

The debrief record should connect each edit to an observed event. If four people pause at the same picture, that pattern offers a clear revision target. One unusual comment may still matter, but a careful team will label it as a single report. This record can improve the next page and keep the result open to inspection.

The fictional materials budget is $120, with 10% held for replacement rolls. The final record includes both instructions, anonymous event sheets, timing summaries, and a careful caveat about the sample. The workshop produces a tested idea and a next method, rather than a universal answer.
